Investigate the assumptions your protocol depends on.

Financial protocols rely on complex relationships between balances, accounting systems, external integrations and privileged operations.

Our focused assessments examine specific components or security questions in depth, with an emphasis on understanding how the system might fail under unexpected but valid conditions.

This service is suitable for:

  • Vault and lending protocol accounting.
  • Bridge and cross-chain asset handling.
  • Staking and rewards systems.
  • Share-price and NAV calculations.
  • Withdrawal queues and settlement mechanisms.
  • Oracle assumptions and price-dependent operations.
  • Proxy upgrades and authorization logic.
  • New protocol integrations.
  • Regression analysis following significant code changes.

From a hypothesis to verified evidence.

  1. 01

    Architecture and threat modeling

    Understand the protocol's intended behavior, trust assumptions, asset flows and critical security boundaries.

  2. 02

    Automated analysis

    Use appropriate static analyzers and AI-assisted tools to identify suspicious paths and generate research hypotheses.

  3. 03

    Independent investigation

    Examine promising leads and determine whether the underlying assumptions and potential impacts are valid.

  4. 04

    Adversarial testing

    Develop targeted tests, stateful invariants, fuzzing scenarios and local exploit reproductions where appropriate.

  5. 05

    Technical reporting and remediation

    Deliver supported findings, realistic impact assessments, limitations and remediation guidance. Retest agreed fixes.

Automated tools assist the investigation. Findings are not treated as confirmed vulnerabilities without supporting technical verification. More detail: our testing methodology.

Frequently asked questions

Can you review code that has already been audited?
Yes. A focused assessment can investigate new releases, integrations, upgrades or areas excluded from earlier audits.
Can we request only one contract or subsystem?
Yes. We define the exact code and integration boundaries before the engagement starts.
Will we receive working exploit tests?
For validated vulnerabilities where a safe local reproduction is feasible, we aim to include reproducible tests. Some findings may require different forms of technical evidence.
Does this certify our contracts as secure?
No. Security reviews reduce uncertainty within an agreed scope; they cannot guarantee the absence of vulnerabilities.
Is remediation included?
The service includes remediation recommendations and one agreed verification round. Implementing production code changes is a separate responsibility unless explicitly contracted.
